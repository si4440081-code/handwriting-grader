# 손글씨 단답형 채점 보조 API (독립 시연 서버)

`손글씨_채점_AI.ipynb` 노트북의 채점 과정을 노트북 밖에서 도는 서버로 옮긴 프로젝트입니다. 멘티가 만든 시연 웹페이지(`web/index.html`)가 부르는 주소를 그대로 제공하므로, Colab 런타임을 켜 두지 않아도 웹페이지로 시연할 수 있습니다.

답안지 사진을 받으면 네 모서리 표시로 반듯하게 펴고, 칸을 자르고, Gemini가 정답을 모른 채 읽고, 신경망이 P(정답)을 계산해 정답, 오답, 선생님 확인으로 나눈 뒤 빨간펜 채점 시험지와 성적표를 만듭니다. 이미 읽은 결과(텍스트)부터 채점하는 주소도 함께 있습니다.

## 실행

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
GEMINI_API_KEY=... .venv/bin/uvicorn api.main:app --port 8000
```

http://127.0.0.1:8000 을 열면 시연 웹페이지가 나오고, http://127.0.0.1:8000/docs 에서 모든 주소를 화면에서 호출해 볼 수 있습니다. 키가 없어도 서버는 뜹니다. 이때 AI가 읽지 못한 칸은 노트북과 마찬가지로 모두 "AI 읽기 키가 없어 읽지 못함 → 교사가 직접 확인"이 됩니다.

예시 답안지는 같은 답안지를 두 번 읽는 `safe` 방식이라, 처음 두 번의 읽기를 동시에 보내고 두 결과가 다를 때만 세 번째를 읽습니다. 서버를 켤 때 예시 답안지를 `READ_WORKERS`장씩 동시에 미리 읽어 두므로, 시연 전에 서버를 켜 두면 예시 답안지는 누르는 즉시 채점됩니다.

AI 읽기가 거절되면 이렇게 처리합니다. 결제 크레딧 없음(402), 잘못된 키, 권한 없음(403), 없는 모델 이름(404), 무료 한도가 0인 모델처럼 다시 시도해도 소용없는 거절은 기다리지 않고 바로 그 칸들을 선생님 확인으로 보냅니다. 칸 사유와 웹페이지 위쪽 안내에 원인이 나오고, 60초 동안은 호출하지 않습니다. 그 사이 충전하거나 설정을 바꾸면 60초 뒤부터 다시 부릅니다. 분당 사용량 제한(429)이나 일시적인 서버 오류는 답안지 한 장의 제한 시간 안에서 다시 시도합니다.

Docker로 실행할 수도 있습니다. 키는 이미지에 넣지 않고 실행할 때 넘깁니다.

```bash
docker build -t grader-demo .
docker run -p 8000:8000 -e GEMINI_API_KEY=... grader-demo
```

웹페이지를 서버와 따로 올렸다면(Vercel, GitHub Pages 등) 페이지 주소 뒤에 `?api=서버주소`를 붙이면 됩니다. 서버는 다른 주소의 페이지가 부를 수 있도록 CORS를 열어 두었습니다.

### 환경 변수

기본값은 노트북 1-2, 5-2절 설정과 같습니다.

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `GEMINI_API_KEY` | 없음 | AI 읽기 키. 없으면 미리 읽어 둔 결과만 씁니다 |
| `GEMINI_MODEL` | `gemini-3.8-flash` | 읽기 모델 이름 |
| `DEFAULT_SUBJECT` | `역사` | 웹페이지에서 처음 고르는 과목 |
| `DEMO_ACCESS_CODE` | 없음 | 정하면 "내 답안지 올리기"에 이 코드가 필요합니다 |
| `DEMO_DAILY_LIMIT` | 40 | 하루에 새로 읽는 답안지 수 상한 (예시 답안지는 세지 않음) |
| `SAMPLE_READ_STRATEGY`, `SAMPLE_TIME_LIMIT` | `safe`, 90 | 예시 답안지 읽기 방식과 한 장 최대 초 |
| `UPLOAD_READ_STRATEGY`, `UPLOAD_TIME_LIMIT` | `fast`, 30 | 새로 올린 사진 읽기 방식과 한 장 최대 초 |
| `READ_WORKERS` | 4 | 동시에 읽는 답안지 수 (분당 사용량 제한에 걸리면 줄이기) |
| `PREFETCH` | `true` | 서버를 켤 때 예시 답안지를 미리 읽어 둘지 |
| `DATA_DIR`, `WORK_DIR` | `data`, `work` | 과목 자료 폴더, 실행 중 만든 파일 폴더 |

## 시연 웹페이지가 부르는 주소

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/` | 시연 웹페이지 |
| GET | `/v1/config` | AI 읽기 가능 여부, 모델, 오늘 사용량과 상한, 접근 코드 필요 여부 |
| GET | `/v1/subjects` | 과목 목록 (기본 과목이 맨 앞) |
| GET | `/v1/samples?subject=` | 과목별 예시 답안지 |
| POST | `/v1/grade/images` | 예시 답안지(`sample_ids`) 또는 올린 사진(`sheets`)으로 채점 → 작업 번호 |
| GET | `/v1/jobs/{job_id}` | 진행률, 끝나면 결과 |
| POST | `/v1/runs/{run_id}/decisions` | 선생님이 확인 문항을 정답(`correct`), 오답(`wrong`)으로 정하거나 되돌림(`undo`) |
| GET | `/files/...` | 답안지, 자른 칸, 빨간펜 채점 이미지와 PDF |

`/v1/grade/images`에 `background=false`를 보내면 작업 번호 대신 채점이 끝난 결과를 바로 돌려줍니다(curl로 시험할 때 편합니다).

```bash
curl -X POST localhost:8000/v1/grade/images -F sample_ids=역사_정해린,역사_김민준 -F background=false
curl -X POST localhost:8000/v1/grade/images -F subject=영어 -F sheets=@내답안지.jpg -F background=false
```

### 정답표, 명렬표, 신경망 바꾸기

웹페이지의 "정답표, 명렬표, 신경망 바꾸기"에 올린 파일(`tables`)은 이렇게 처리합니다. 노트북 5-2절의 서버는 이 파일을 받기만 하고 쓰지 않았는데, 웹페이지 안내문과 노트북 3-7절 설명대로 동작하도록 만들었습니다.

| 올린 것 | 채점에 쓰는 것 | 웹페이지의 신경망 안내 |
|---|---|---|
| 없음 | 고른 과목의 정답표, 명렬표, 신경망 | 이 정답표로 학습한 신경망 |
| 정답표 | 올린 정답표로 그 자리에서 다시 학습 (1초 안팎) | 이 정답표로 학습한 신경망 |
| 명렬표만 | 과목 정답표 + 올린 명렬표 | 과목 신경망 그대로 |
| grader.json (노트북 3-7에서 내보낸 것) | 그 신경망. 정답표 지문이 다르면 경고 | 노트북에서 학습해 올린 신경망 |

CSV, TSV, 엑셀 모두 받고, 엑셀 한 파일에 정답표와 명렬표 시트를 같이 넣어도 됩니다. 열 이름이 조금 달라도 알아듣습니다(문제번호 → 문항, 점수 → 배점, 성명 → 이름).

## 과목 자료 넣는 법

`data/subjects/과목이름/` 폴더 하나가 과목 하나입니다.

- 정답표와 명렬표: CSV나 엑셀 아무거나 (지금은 멘티가 만든 `과목_시험자료.xlsx`)
- `sheets/`: 예시 답안지 사진. 파일 이름이 웹페이지에 보이는 제목입니다
- `grader.json` (선택): 노트북 3-7에서 내보낸 신경망. 정답표 지문이 같을 때만 쓰고, 다르면 다시 학습합니다

노트북에서 미리 읽어 둔 결과(`gemini_cache.json`)를 `data/gemini_cache.json`에 넣으면, 키가 없어도 그 답안지는 AI 읽기 결과로 채점됩니다. 노트북은 1~4단계에서 채점한 과목의 답안지를 과목 이름 없이 저장하므로, 이름이 맞는 것은 기본 과목(`DEFAULT_SUBJECT`)의 예시 답안지뿐입니다. 다른 과목은 노트북 5-2절에서 읽은 결과가 그대로 맞습니다.

## 노트북과 같은지 확인한 방법

| 확인 | 결과 |
|---|---|
| 노트북 셀(1-2, 1-4, 1-5, 2단계, 3-3)을 직접 실행해 과목 5개 정답표로 시뮬레이션 데이터 3,000개씩 생성 | 특징 8개, 정답여부, 답 유형, 한 글자 차이 여부 15,000행 모두 같음 |
| 예시 답안 235개(+엇갈린 읽기 변형)의 특징, 판정 규칙 사유를 지저분함 2가지, 엇갈린 읽기 규칙 3가지, 칸 밖 2가지로 비교 | 470칸 모두 같음 |
| 정답표 지문 | 과목 5개 모두 노트북 3-7 계산식과 같은 값 |
| numpy 학습과 Keras 학습 (시뮬레이션 데이터, 시드 5개) | 학습에 쓰지 않은 데이터의 정확도 범위가 겹침. 영어 Keras 0.891~0.915, numpy 0.902~0.917 |
| 예시 답안지 38장 정렬 | 모두 모서리를 찾음. 역사 정해린의 칸 밖 글씨 1, 2, 4번이 사진과 맞음 |
| 멘티의 `예시_답안지_설명.txt` 의도 (테스트) | 과목 4개 × 6장이 01, 02 모두 정답, 03 모두 오답, 04 선생님 확인(빈칸은 오답), 06 학생 식별 문제로 판정됨. 아래 알려진 차이 1칸은 예외 |

테스트(`pytest`)는 실제 예시 답안지 사진을 정렬하고 자르되, Gemini 호출만 학생이 실제로 쓴 답(`tests/fixtures/정답_실제.csv`)을 돌려주는 가짜 읽기 함수로 바꿔 끼웁니다. 실제 Gemini 호출은 2026년 11월 3일 키를 연결해 직접 쓴 답안지로 확인했습니다. 그 결과 화면은 `results/`에 있습니다.

## 알려진 차이와 한계

- ⚠️ **순서 바뀜 판정 (노트북과 같은 동작)**: "순서만 다름"을 가장 가까운 허용 답안 하나와만 비교합니다. 과학 3번처럼 더 짧은 허용답안("중화")이 있으면 "반응중화"가 "중화 반응"의 순서 바뀜으로 잡히지 않고 자동 오답이 됩니다. 멘티 설명 파일의 의도(선생님 확인)와 다릅니다. 서버만 따로 고치면 노트북과 판정이 달라지므로 그대로 두었고, `tests/test_engine.py`에 `xfail` 테스트로 남겼습니다. 노트북 1-5절의 `순서만다름`을 "허용 답안 중 하나라도 글자 구성이 같으면"으로 바꾸고 서버도 같이 바꾸면 그 테스트가 통과로 바뀝니다.
- 채점 결과는 메모리에 있어 서버를 다시 켜면 선생님 판정이 사라집니다(노트북과 같음). AI 읽기 결과는 `work/gemini_cache.json`에 남습니다.
- 올린 사진과 채점 결과 파일을 지우지 않습니다. 오래 띄워 둘 서버라면 `work/uploads`, `work/runs`를 주기적으로 지워야 합니다.
- 노트북의 칸마다 읽기(`READ_MODE = 'cell'`)와 모델 자동 고르기(`AUTO_PICK_MODEL`)는 옮기지 않았습니다. 서버는 한 장 모아 읽기만 하고, 모델은 `GEMINI_MODEL`로 정합니다.
- 시험지 칸 좌표는 1~5번 문항만 있습니다. 6번 이상이 있는 정답표는 그 문항을 채점하지 않고 경고를 보여 줍니다.
- 웹페이지 접근 보호는 시연용 접근 코드와 하루 상한뿐입니다. 공개 주소로 올릴 때는 두 값을 정하세요.

## 텍스트 채점 주소

이미 읽은 결과부터 채점합니다. 판정 기준은 시연 서버와 같습니다.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/health` | 모델 정보 |
| POST | `/v1/grade/csv` | 정답표, 명렬표, 학생 답안 표(CSV, 엑셀)를 올려 채점 |
| POST | `/v1/grade` | 같은 내용을 JSON으로 보내 채점 |

학생 답안 표의 칸 표시는 노트북과 같습니다(`*` 지저분한 칸, `!` 칸 밖 글씨, `|` 여러 번 읽은 결과). 예시 답안 155칸은 기본 판정 기준에서 정답 87, 오답 37, 교사 확인 31입니다. 이 주소가 쓰는 `models/grader.json`은 `python -m training.train`(TensorFlow 필요, `requirements-train.txt`)으로 다시 만들 수 있습니다.
